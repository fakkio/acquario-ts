# Future ideas

Unshaped ideas for later versions, logged before they're worth a `vision.md` section, an ADR or a ticket. An idea graduates out of this file the moment it lands in `vision.md`, an ADR or an issue — delete it here at that point rather than leaving it duplicated.

- A founder archive: the next world's generation 0 mutated from genomes carried forward from the last, holding the seed pinned so genetics is the only axis that varies between worlds (ADR-0018 — in-session memory only, and the selection criterion is deliberately still open). What would make it worth persisting rather than keeping in memory: carrying the archive across launches, so reopening AcquarioTS resumes from the genomes the last session ended on. That needs persistence v0.1 does not have and a genome schema worth versioning, which the four-field record on its way to `Gene[]` is not — so it waits for v0.2 rather than for M5, whose done-criteria runs require cross-run inheritance to be off anyway (ADR-0018).
- Food as ballast, the Kromkamp–Walsby loop (#44, ADR-0030): a cytoplasm lighter than water and a food store denser than it, so a body fed in the light sinks and one respiring in the dark rises, and each organism tracks the depth where its store is steady. It emerges from chemistry that already exists, but it moves the minimal organism from generation 0, and a parent must hold more food than the neutral level to breed, so it sinks exactly when it is ready. Worth trying once calibration has margin, as the passive route to depth that needs no organelle.
- Photoinhibition: light above an optimum slowing photosynthesis (Visser et al. 1997), as a counter-pressure against the surface crowd. Stratified water already gives v0.2 interior resting depths (ADR-0030), so it waits until the surface proves too crowded anyway; it changes v0.1's light law when it comes.
- A thruster that pushes harder the closer it sits to the membrane, since a flagellum anchors there (#49, ADR-0032). Set aside because the distance to the membrane depends on the other organelles, which set the enclosing circle, so a chloroplast inserted further out would weaken a thruster that never changed. Worth revisiting if the lever arm alone gives thruster placement too little meaning.
- A float whose density a signal regulates, exposing its density as an output port (#49, ADR-0032). It is a second actuator: free, it makes holding a depth free and takes the thruster's vertical role; priced, it needs a cost law of its own. Real gas-vesicle regulation is slow and costly.
- A chloroplast exposing its fixation rate as an output port (#49, ADR-0032). Today it nearly duplicates the `light` and `CO₂` innate senses, and every chloroplast would add a source to the uniform synapse draw. Worth it if light ever varies a lot within one body.
- Environmental cycles (#51, ADR-0033): the Bright Zone slowly narrowing and widening again, or other slow periodic changes, so those that cannot follow die and return their carbon. Three gains at once: turnover in a world limited by mass, a use for the nervous system (following a moving light with `light` → thruster, where composition only gives a fixed depth), and a use for the storage vesicle, deferred because constant light leaves nothing to buffer against. The cost: the Bright Band is the window `α` is measured through (ADR-0015, ADR-0023), so `α`, `k` and every depth report would have to be measured over a whole cycle. A candidate theme for a later version, perhaps with the vesicle.
- A reason for a neuron to be large (M7 grill, for M11). A neuron's size and position mean only cost and space (ADR-0031), so a radius buys nothing and selection drives every neuron to the radius floor. Two candidates, neither convincing yet: channel noise scaling as `1/√area`, so a small neuron is cheap but noisy, as real neurons with few ion channels are, at the price of one draw per neuron per tick; or fan-in bounded by perimeter, a neuron accepting at most a number of synapses proportional to `2πr`.
- Walsby's collapse depth for the float: wider gas vesicles lift more but collapse shallower (#44, #49). It needs a pressure law the stratified column does not have.

- Passive photosynthesis and passive respiration rates proportional to body area rather than to diameter, which would create a genuine trade-off between diameter and body area. Respiration already scales with area; photosynthesis currently scales with diameter, and that choice is what keeps energy income linear in `r`, the assumption `r_opt = 2·c₀/α` rests on — moving it to area needs that derivation reworked too.
- Decouple the Uniform Grid's cell size from the population it indexes. Today `cellSize` is rederived every tick as twice the largest `bodyRadius` alive (`grid.ts`), so one outsized organism coarsens the whole grid and every `query()` call recomputes its row/column bounds and loops that rectangle from scratch. Two changes together would fix this: (1) pick `cellSize` once, offline, by benchmarking candidate sizes against a representative population rather than deriving it from whoever is currently biggest; (2) since a fixed cell can now be smaller than some bodies, bucket each organism into every cell its body overlaps, not only the cell its centre falls in — otherwise a query could miss a body whose bulk crosses into the search area while its centre sits just outside it. The payoff for fixing the cell size is that the rectangle of cells a query has to visit becomes a shape that depends only on the search radius and can be precomputed once: a map from ring distance (0, 1, 2, …, in cell units) to the list of cell offsets at exactly that Chebyshev distance from the origin cell (0 → `(0,0)`; 1 → the 8 adjacent cells; 2 → the 16 cells one ring further out; and so on). `query(x, y, radius)` then converts `radius` to a ring count, looks up the organism's own cell once, and walks that many precomputed rings outward from it — table lookups instead of a fresh bounds computation and nested loop on every call. Multi-cell bucketing means the same organism can surface from more than one ring, so `query` should return a `Set<Organism>` rather than an array to dedupe for free — `forEachNeighbour` in `separation.ts` currently calls its visitor once per candidate with no dedup of its own, and a repeated candidate there would apply a positional-separation correction twice. Before committing to this design, benchmark it against the current variable-cell grid and against a quadtree, side by side: the variable-cell grid's existing rationale for not using a tree (`grid.ts`'s docstring, bucketing is O(n) against a tree's O(n log n) subdivision) assumed cell size scales with the largest body, which is exactly the assumption a fixed cell size drops — a quadtree may turn out to win precisely in the case this idea is weakest at, a population with one outsized organism among many small ones, since a tree adapts to the size distribution instead of paying for it through multi-cell registration. Whichever wins should also settle whether ADR-0012 needs revisiting, not just this file.
